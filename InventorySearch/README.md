# 增强背包搜索

使用 `/ebsearch` 打开窗口。原 `/isearch` 因与游戏原生文本指令冲突而停用。插件按角色将已加载的数据保存到 Dalamud 的插件配置目录，数据不会上传。

自动记录：

- 四页角色背包
- 普通与高级陆行鸟鞍囊
- 每一名已打开过的雇员
- 已打开并加载的幻化台
- 已加载的收藏柜

游戏只会把当前打开过的远程存储发送给客户端。因此首次安装后，请分别登录各角色，并至少打开一次鸟包、每名雇员、幻化台/收藏柜。旧角色和未打开存储使用上次成功快照，不会被空数据覆盖。

鸟包采用分页增量保存：客户端当前加载哪一页就只更新哪一页，其余未加载页面继续保留本地旧快照，不会被当成空包覆盖。首次建立索引或需要读取本次登录后的最新变化时仍需打开一次鸟包，这是游戏按需下发数据的限制；建立过的本地索引不会仅因未打开鸟包而消失。

雇员索引使用更严格的完整快照规则：必须处于传唤铃交互状态、原生雇员背包窗口可见且七页容器全部加载，才会更新对应雇员。列表切换期间残留的活动雇员 ID、尚未加载的页或已经关闭的窗口都不会覆盖旧索引。

## 从雇员直接取出

登录记录所属角色并站在传唤铃的可交互范围内后，可以在雇员搜索结果右侧直接输入数量，也可以使用数字框两侧的 `-` / `+` 按钮调整，然后点击“取出”。插件会打开雇员列表、呼叫对应雇员、进入原生雇员背包界面，再通过游戏原生的“取出”或“指定数量取出”流程把道具放入角色背包。

为防止旧快照导致误操作，移动前会重新核对角色、雇员 ID、原生雇员背包窗口、背包栏位、道具 ID、品质和数量；任一信息变化都会取消操作。每次只处理一项，不会连续取物，完成后会保留雇员界面。

### 批量取出

雇员搜索结果左侧可以勾选多个格子。点击“批量取出”后，每个勾选格都会严格按照该行右侧的独立数量框取出；各行数量均支持直接输入并保留 `-` / `+` 按钮。

数量不足、不是当前登录角色的记录会在开始时跳过并计数。同一雇员的项目连续处理，切换雇员时才自动结束当前对话并重新呼叫；全部完成后关闭雇员窗口。任一格在执行时校验失败会停止剩余队列，避免继续使用旧快照。

## 可堆叠物品

分类筛选中选择“可堆叠物品”，可以查看角色背包里能够并入雇员现有堆叠的道具。每条记录会显示目标雇员、目标格当前数量、该物品的实际单格堆叠上限和当前最多可存数量。

数量支持直接输入，也可以使用 `-` / `+` 调整。插件只允许存入到目标格剩余容量为止；正式操作前还会读取原生来源格、目标格和游戏数量输入框的上下限重新校验。

点击“存入”时会先确认角色处在传唤铃交互范围内，然后依次打开雇员列表、选择目标雇员并执行原生存入。数量验证成功后，插件会关闭雇员背包、选择结束对话并关闭雇员列表。若道具已经存入但关闭界面超时，会保留成功结果并提示手动关闭，不会重复存入。

插件发起的取出、存入或整理过程中若出现游戏的普通 `Talk` 对话，会自动推进；出现“是/否”确认对话时会自动选择“是”。没有插件物品操作时不会干预普通对话或确认框。

跨雇员切换时，插件会同时检查窗口和游戏的 `OccupiedSummoningBell` 状态。即使雇员列表已经消失，只要上一位雇员的交互状态尚未完全释放，就会继续等待并处理残留对话，而不会误报“请先结束当前雇员对话”或提前终止存入。

可堆叠物品列表也支持勾选后“批量存入”，每条记录使用该行自己的数量。插件会累计检查同一背包来源格的剩余数量和同一雇员目标格的剩余容量；同一雇员连续处理，切换雇员时才关闭当前窗口。超出来源数量或单格最大堆叠数的条目会跳过。

是否仍在与雇员交互以游戏条件 `OccupiedSummoningBell` 为准；客户端残留的上一次活动雇员 ID 不会被误判为仍在对话。

## 跨雇员堆叠整理

点击“跨雇员堆叠整理”可查看合并建议。建议会根据物品数据表中的实际 `StackSize`，选择来源雇员、目标雇员与不会超过单格上限的搬运数量。

整理建议支持逐项勾选，也可对单条点击“自动合并”。开始后插件会按“来源雇员 → 目标雇员”分组：一次呼叫来源雇员并连续取出组内全部道具，再一次呼叫目标雇员并连续存入全部道具，避免每件物品分别往返。每一步都会重新核对物品、品质、格子数量和目标堆叠容量；异常时停止剩余队列。
